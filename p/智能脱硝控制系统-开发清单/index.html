三、已实现功能全景

界面框架（v1.1.0 新增）

  • 左侧深色固定侧边栏 + 顶部紧凑状态条（CSS Grid 三区布局）
  • 侧边栏宽度可拖拽调整（160-360px），localStorage 持久化
  • 侧边栏自包含登录弹窗（切换账号/顶条用户区点击）
  • 工业控制台主题（冷灰 #e8ecf0 背景 / 2-3px 微圆角 / 强语义色 / 零毛玻璃零渐变）
  • 顶栏系统状态指示器（Modbus/PID/报警/保存）+ 仪表盘顶栏状态灯组件
  • 14 个导航链接（仪表盘为首），当前页蓝色竖条高亮，无权限页面半透明加锁

Modbus 通讯（主机）

  • RTU/TCP 双协议，连接/断开按钮 + 后台轮询/停止
  • 停止轮询自动断开物理连接 + 释放串口/TCP 端口
  • 多数据类型 uint16/int16/uint32/int32/float32/float64
  • 字节序 BE/LE + 字序 ABCD/BADC/CDAB/DCBA
  • 报文帧 hex 调试（请求/响应，含 CRC 校验显示）
  • 操作队列串行化（enqueue，防并发冲突）
  • PID 写入短超时队列路径（1200ms）+ 退避保护
  • 连接健康心跳（30s 独立检测）+ 智能断线重连（3 次失败触发）
  • 重连冷却期保护（10 秒锁频防抖）
  • 冷启动自适应超时 + PID 写入拥塞预检

Modbus 从机（v1.1.0 TCP Server 新增）

  • RTU 从机 (ServerSerial) + TCP 从机 (ServerTCP)，主从模式可同时运行
  • 解析规则表统一服务主机解析 + 从机映射（共用 modbus-parse-rules.json）
  • 从机帧捕获 + RS-485 回显过滤
  • 从机诊断统计 + 事件日志
  • 多寄存器缓存机制（_slaveRegCache_*），防部分写入产生中间值
  • PID 输出寄存器和报警寄存器自动注入从机映射

Modbus 配置文件统一（v1.1.0）

  • modbus-connect.json：主机 + 从机连接参数统一文件（master / slave 对称结构）
  • modbus-parse-rules.json：主机/从机共用寄存器解析规则（registerMap 统一键名）
  • modbus-parse-rules.factory.json：出厂默认模板（首次启动种子）
  • 向前兼容：旧 modbus.json / modbus-slave.json / modbus-slave-config.json 自动迁移
  • 解析规则加载兼容 registerMap / rules 两种键名

后台轮询与自动保存

  • 主进程定时轮询，页面切换后继续运行
  • 并发保护 + 连续失败检测 + 强制重连
  • 重连冷却期（10s，防健康检查重复触发）
  • 休眠唤醒后自动恢复（断开→等待 1.5s→重连→恢复轮询）
  • 自动保存（独立定时器，周期性写 SQLite）
  • 保存变量过滤器（只保存勾选的字段）

数据处理管线（dataPipeline）

  • 自持状态：过滤器配置/补偿配置/计算变量/运行时状态全部模块内管理
  • 寄存器解析（按规则表顺序 + 类型校验）
  • 4 种数据过滤器：范围钳位/变化率限制/移动平均/尖峰抑制
  • 仪表状态补偿（状态机模式 + 跟随模式，AND/OR 条件逻辑）
  • 安全计算变量引擎（vm 沙箱，三道防线：黑名单→白名单→空原型沙箱）
  • 伴生变量体系：XXX(过滤) + XXX(补偿) + <规则名>_compensating

PID 控制（pidOrchestrator）

  • 多实例 PID 控制器（增删/Tab 切换）
  • 位置式 PID + 积分抗饱和 + 微分先行
  • PV 低通滤波 / 死区 / 输出变化率限制
  • ★ 反向作用（Reverse Action） — 脱硝等负增益过程，error = PV − SP
  • ★ 前馈控制（Feed-forward） — 可测扰动直接叠加到输出
  • ★ 增益调度（Gain Scheduling） — 根据工况变量动态缩放 P/I/D 系数
  • ★ 史密斯预估器（Smith Predictor） — 补偿 3~15 分钟纯滞后
  • ★ 手动/自动无扰动切换（Bumpless Transfer）
  • 远程复位信号（上升沿触发，只响应 0→1）
  • ECharts 实时趋势（SP/PV/预估 PV/总输出/修正 五曲线 + 偏差带虚线）
  • 健康指示灯（输出饱和 + 偏差状态 + 偏离持续时长）
  • 周期溢出检测 + 定时器卡死看门狗

内部变量系统

  • internalVariables 全局数据中心（对象共享，按引用传递）
  • 变量元数据注册表（单例，category/description/unit/writable）
  • 分类筛选：全部/Modbus/PID/手动/计算/系统/AI
  • 30+ 系统健康指标（含 4 个 AI 状态变量）
  • 变量上限 500 防护（MAX_INTERNAL_VARIABLES）

数据存储

  • SQLite (WAL 模式) — datastore.sqlite / auth.db / alarm_history.sqlite / audit_log.sqlite
  • 自动建列 + 数据库列管理
  • 聚合查询（分钟/小时/天 AVG/MIN/MAX），动态 SQL 生成
  • 每日凌晨 3:00 自动备份
  • 过期数据自动清理（保留 N 天，默认 180 天）

报警管理

  • 看门狗心跳 + 阈值报警 + 三级分级（预警/报警/严重）
  • 延时触发（倒计时显示）+ 滞后死区
  • 报警历史 SQLite 记录 + 桌面通知
  • 仪表盘报警摘要组件（自动展示全部活跃报警）

仪表盘（v1.1.0 重写布局引擎）

  • 12 列显式 CSS Grid 自由布局（替代旧 auto-fit 流布局）
  • 自由拉伸：右下角三角手柄，2-12 列 × 1-6 行无极调节
  • 拖拽移动：⋮⋮ 手柄拖拽 + 半透明占位 ghost + 网格吸附 + 位置交换
  • 10 种组件：数值卡片/状态灯/顶栏状态灯/可编辑数值/折线图/柱状图/环形仪表盘/进度条/控制路由/报警摘要/补偿摘要
  • 报警摘要 + 补偿摘要：自动获取系统数据，无需配置数据源
  • 顶栏状态灯：逻辑与状态指示灯一致，同时在顶部状态条渲染
  • 布局持久化：{ x, y, w, h } 存入 localStorage + 文件（向后兼容旧 size 格式）
  • 组件注册表模式（dashboardWidgets.js）+ 增量渲染
  • 聚合模式（分钟/小时/天均值）

AI 推理引擎（v1.1.0 退避机制）

  • 双定时器架构（采样 + 请求，完全解耦）
  • 连续 3 次失败自动退避：停请求定时器，切慢速探测（30s 一次）
  • 探测成功自动恢复：重启请求定时器，切回正常频率
  • 4 个 AI 系统变量（_sys_ai_enabled/connected/consecutive_failures/success_count）
  • 变量监控页面 AI 分类筛选

用户管理与授权

  • 三角色（admin/operator/viewer）+ 可配置权限矩阵
  • 硬件指纹 + AES-256-CBC 授权码激活
  • 3 天试用期 + 丰富的授权信息展示（剩余天数/起止日期/到期警告）
  • 自动登录（无人值守）+ 会话超时降级
  • 侧边栏切换账号（自包含登录弹窗）
  • 登录审计 + 操作审计

系统与安全

  • contextIsolation: true + nodeIntegration: false（进程严格隔离）
  • 所有 IPC 通过 invoke/handle（无 on/send 裸通道）
  • 配置原子写入（tmp + copyFile + unlink，防断电损坏）
  • 配置备份与恢复（动态扫描 data/，选择性导出/导入）
  • 系统托盘 + 最小化到托盘
  • 电源休眠阻止 + 休眠唤醒全自动恢复
  • 代码混淆保护（打包时自动）

五、已闭环的安全与稳定性防线

5.1 进程隔离

  • 渲染进程 contextIsolation: true，nodeIntegration: false
  • 所有 Node.js API 通过 preload.js 的 contextBridge.exposeInMainWorld 暴露
  • IPC 全部使用 ipcRenderer.invoke ↔ ipcMain.handle 模式，无通配符通道
  • 110+ API 通道，零 send/on 裸调用

5.2 IPC deps 访问器兼容设计

  • 所有 IPC 模块通过 register(deps) 接收依赖注入
  • main.js 的 deps 对象使用 getter/setter 代理到各 core/ 模块
  • 前端和 IPC 模块完全无感于底层模块拆分

5.3 Modbus 字节重排去重

  • 统一提取到 modbusUtils.js，主从双方共享同一份实现

5.4 PID 无扰动切换

  • 自动→手动：反算积分项对齐当前输出（输出零跳变）
  • 手动→自动：积分从对齐值平滑接管

5.5 定时器幂等清理与看门狗

  • 所有 start* 函数内部先 clear* 旧定时器再创建
  • PID 定时器卡死看门狗：3×采样周期强制释放

5.6 配置原子写入

  • ConfigManager.save() 三步：tmp → copyFile → unlink

5.7 AI 退避与自动恢复

  • 连续 3 次失败 → 停请求定时器 → 30s 慢速探测 → 成功自动恢复
